# Anti-slop

"AI slop" is not a font or a color. It is the absence of a product decision, replaced by a familiar visual reflex. The result can look polished at a glance and still tell you nothing about what the product is for.

## Signals, not bans

The patterns below are suspicious because they often substitute for thought. Any one can be legitimate with a specific reason. Several together usually indicate an unconsidered interface.

- Purple-to-blue gradient hero with no brand rationale.
- Glass panels, backdrop blur, and translucent cards on every surface.
- Rounded cards floating on a gradient background.
- Oversized display type that repeats the obvious.
- Three generic feature cards with icons.
- Fake dashboard metrics used as decoration.
- Generic "AI" sparkle icons.
- Excessive pill shapes.
- Emoji used as iconography in a serious workflow.
- Hover-only reveal for essential actions.
- One perfect viewport screenshot with no empty, error, or mobile state.
- Copy such as "Elevate", "Seamless", "Unlock", "Effortless".
- Decorative labels like "Insights" or "Intelligence" with no data.

The audit flags gradients and glass because they are common defaults. It cannot know whether your brand has a real reason. A justified gradient is fine; a default gradient is not.

## The product-decision test

For each prominent visual choice, ask:

1. What user or product problem does this solve?
2. What would be lost if it were removed?
3. Is it specific to this product, or could it belong to any SaaS page?

If the answer to (3) is "any product", the choice is probably decoration.

## Composition without cards

Cards are easy because they create instant boundaries. They also flatten hierarchy and add borders, padding, and shadows that the content did not ask for.

Try:

- a single reading column with strong section rules;
- a table with generous row spacing instead of each row as a card;
- an asymmetric split where one side carries the task and the other carries context;
- a side rail for navigation and metadata, with the main body kept calm;
- one strong typographic statement instead of five bordered boxes.

## Metrics with meaning

A metric needs:

- a definition;
- a time window;
- a unit;
- a comparison;
- a source;
- a reason the user should care.

A number without those is decoration. If the product is a demo, label it as demo data. Do not invent a plausible-looking graph and present it as evidence.

## Copy that earns its space

Replace:

- "Powerful insights" → "Requests per hour, by region";
- "Seamless collaboration" → "Invite a teammate and assign a role";
- "Next-generation security" → "Require SSO for every workspace member";
- "Unlock your potential" → "Export the last 30 days as CSV".

Specificity is the strongest anti-slop tool.

## Images and illustrations

- Use real product screenshots, real data shapes, or a deliberate visual system.
- Avoid stock illustrations that could sell anything.
- Do not use an illustration where a concrete example would answer the question.
- If you use abstract art, give it a compositional role, not just a colorful corner.
- Optimize and credit assets. Do not scrape images you cannot license.

## Motion

Motion should explain:

- where something came from;
- what changed;
- what is now possible.

It should not be the personality. A page that animates every section into view is usually hiding the fact that the sections do not say much.

Respect reduced motion. Keep critical content visible even if animation fails.

## The swap test

Try these:

- Swap the logo and product name. Does the design still work for a different product? If yes, it is probably generic.
- Remove all gradients and shadows. Does hierarchy survive? If not, hierarchy was relying on decoration.
- Replace the hero copy with a factual sentence. Does the page still sound like the product?
- Show the interface with empty data. Does it still explain itself?
- Show it at 390px. Does the composition still have a point of view?

## Redesigning a slop page

1. Identify the real task and the real user.
2. Remove decoration that does not carry meaning.
3. Establish a reading order.
4. Use type, space, and alignment to create hierarchy.
5. Add one distinctive element that comes from the product's domain, not from a trend.
6. Build the empty, error, and mobile states.
7. Replace generic copy with specific language.

The goal is not minimalism for its own sake. The goal is intention. A dense, expressive interface can be excellent if every element is doing work.

## Review checklist

- [ ] The primary task is visible without scrolling through decoration.
- [ ] Every section has a product reason to exist.
- [ ] Metrics have definitions and sources.
- [ ] Copy names objects and actions, not vibes.
- [ ] Gradients, glass, shadows, and radii have a role.
- [ ] The design survives without its decorative effects.
- [ ] Empty, error, and mobile states are designed.
- [ ] The interface does not pretend to have data it does not have.
- [ ] The visual language is specific to the product.
- [ ] Nothing is present only to fill space.
